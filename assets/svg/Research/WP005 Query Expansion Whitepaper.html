ABSTRACT

This paper documents pre-build validation research for a Query Expansion module planned as a future feature addition to AI Spider, a proprietary locally-hosted website crawler and AI retrievability audit platform. It is the fifth paper in a series validating AI Spider's planned content intelligence layer, following WP001 (Competitive Content Intelligence), WP002 (Coverage Score), WP003 (Retrieval Drift), and WP004 (Coverage vs Confidence).

WP001-004 validated four evaluative modules - each taking a target page and measuring it against some standard. The Query Expansion module is structurally different: it is generative, not evaluative. It runs before any page analysis begins, expanding a user's prompt into a complete topic universe - synonyms, related concepts, subtopics, named entities, and alternative queries - that all other modules use as their reference set. Without an accurate topic universe, every downstream coverage score, entity gap, and drift calculation is anchored to an incomplete or inaccurate baseline.

This also means the failure modes are different. WP001-004 failures were analytical: role confusion, coverage inflation, dimension conflation. WP005 failures are generative: hallucination (inventing entity names that do not exist), omission (missing major real entities), and vagueness (generating non-specific concepts that do not help downstream analysis). Research involved designing a zero-content prompt (no page data provided), building a two-vertical test set (AI/GEO tools and digital marketing agency), establishing a ground truth entity list from domain knowledge, and benchmarking three frontier models.

Research Conclusion

All three frontier models produced valid, useful topic universes for both verticals. The most important finding is model-specific hallucination: Gemini 3.5 Flash generated three entities in V1 that do not exist as named products (BrightEdge Generative Parser, Moz AI Analytics, Preora), and one in V2 (HawkSEM is real but misclassified). Claude Sonnet 4.6 produced the cleanest entity list - all verified real - with the strongest synonym quality. ChatGPT GPT-5.5 generated the most comprehensive entity set across both verticals including entities from WP001-004 competitor pages. Gemini's subtopic framing was notably more strategic than Claude or ChatGPT, showing the most distinctive expansion style of the three. The module will use Claude as default with a post-processing entity verification step.

SECTION 1
Background and Research Motivation

Every module validated in WP001-004 begins with the same assumption: that the analytical engine knows what topics, entities, and concepts are relevant to the user's query. In WP001, the CCI module compares pages against each other - but it can only identify a gap if it knows the gap exists. In WP002, the Coverage Score generates an expected topic set - but only in Stage 1 of the analysis prompt. In WP003, drift is detected relative to query intent - but the intent must be defined somewhere. In WP004, confidence signals are measured against expected evidence - but the expectation must come from somewhere.

"Every content intelligence module in AI Spider is only as good as its topic universe. If the universe is incomplete, gaps go undetected. If it contains hallucinated entities, false gaps appear. The Query Expansion module is the foundation the entire content intelligence layer rests on."

The Query Expansion module formalises this foundational step. Rather than embedding topic generation inside each module's prompt as an incidental step, it makes topic universe generation a dedicated, standalone operation with its own quality criteria, its own failure modes, and its own validation benchmark. The generated universe is stored and reused across all subsequent analyses for that query - ensuring consistency across CCI, Coverage Score, Retrieval Drift, and Coverage vs Confidence analyses.

This research was motivated by three observations from the WP001-004 benchmark series:

  • O1Stage 1 quality was the ceiling in WP002. When models generated too few expected topics, coverage scores were systematically inflated. A dedicated Query Expansion step with quality validation prevents this from happening before analysis begins.
  • O2Entity lists varied significantly across WP001-004 benchmarks. Different modules identified different entities for the same query. A shared Query Universe generated once and reused across modules eliminates this inconsistency.
  • O3No page content is required for this task. The module generates a topic universe from the prompt alone - making it the first AI Spider content intelligence feature that can run without crawling any URL. This enables pre-analysis planning before a user selects their target or competitor pages.

Before building the module, three research questions needed validation:

  • Q1Entity accuracy: do models hallucinate tool or brand names? Unlike WP001-004 where models worked from provided text, here models generate entities from memory. Hallucination risk is real and consequential - a hallucinated entity in the topic universe will propagate as a false gap into every downstream analysis.
  • Q2Expansion completeness: do models miss major real entities? The opposite risk to hallucination. A missing entity means a real gap in the universe - and a real gap in every downstream coverage and entity analysis that relies on it.
  • Q3Layer quality: are synonyms, subtopics, and related concepts genuinely useful? The module generates six layer types. Each must be specifically useful for downstream analysis, not a generic list that could apply to any query.
SECTION 2
Research Methodology
2.1
The Six-Layer Topic Universe

The Query Expansion module generates a topic universe across six layers. Each layer serves a specific downstream purpose. The layers are not interchangeable - each feeds a different analytical capability in the AI Spider content intelligence suite.

Core Topic
The central concept Defines the scope of the entire universe. All other layers expand outward from this anchor. Used by all modules as the query intent statement.
Synonyms
Alternative phrasings of the same concept Used by Coverage Score to recognise when a page addresses the topic under a different name. Critical for avoiding false negatives in coverage evaluation.
Related Concepts
Adjacent ideas in a complete answer Used by CCI and Coverage Score to identify what a comprehensive page should address beyond the literal query. Distinct from subtopics - these are conceptual neighbours, not sections.
Subtopics
Sections or categories a comprehensive page would include Used directly as the expected topic set in Coverage Score Stage 1. Quality here directly determines coverage score accuracy.
Named Entities
Real, named brands, tools, platforms, frameworks, certifications Used by CCI for entity gap analysis and by Coverage vs Confidence for entity confidence signals. Hallucination here is the highest-risk failure mode - a false entity propagates through all downstream analyses.
Alternative Queries
Common intent variations of the original query Used by Retrieval Drift to understand what related queries a page might be optimised for, and by RankScan to expand monitoring scope beyond the primary query.
Figure 1. The six topic universe layers and their downstream uses. Each layer feeds a specific AI Spider content intelligence module. The Named Entities layer carries the highest risk - hallucinated entities propagate as false gaps into CCI, Coverage Score, and entity expansion analyses.
2.2
Prompt Design

The WP005 prompt is the simplest in the series - no page content, no competitor content, just the query and structured output instructions. This simplicity is intentional: the module's value is generating a reliable topic universe from domain knowledge alone. The prompt explicitly prohibits entity invention, requires the model to confirm entity existence before including it, and specifies target counts for each layer to prevent either sparse or bloated outputs.

Prompt Template - v1.0 No page content - query only
Both verticals identical structure

// SYSTEM ROLE

You are a Query Expansion engine. Expand the user's PROMPT into a complete topic universe for content analysis.

No page content is provided. Generate from your domain knowledge.
Do not invent entity names. Only include real, named entities you are confident exist.

// OUTPUT STRUCTURE - 7 sections

1. CORE TOPIC - one clear phrase
2. SYNONYMS - 4-6 distinct alternative phrasings
3. RELATED CONCEPTS - 6-10 adjacent ideas expected in a complete answer
4. SUBTOPICS - 6-8 sections a comprehensive page would include
5. ENTITIES - 10-15 real named brands, tools, platforms, certifications only
6. ALTERNATIVE QUERIES - 4-6 intent variations of the original query
7. QUERY UNIVERSE SUMMARY - flat list of all unique items with total count
Respond only with the structured output. No commentary outside the format.
Figure 2. Full prompt template. No page content is embedded - the model generates entirely from domain knowledge. The "do not invent entity names" instruction is the critical safety constraint for the Named Entities layer. Target counts for each layer (4-6 synonyms, 10-15 entities) prevent sparse or inflated outputs that would skew downstream analysis.
2.3
Two-Vertical Test Set and Ground Truth

Because no page content is provided, ground truth for WP005 is established differently from WP001-004. Instead of checking model outputs against page text, ground truth is domain knowledge - what entities, concepts, and subtopics an expert in each vertical would independently identify as essential. Ground truth was compiled before running any model tests.

  • V1AI/GEO Tools - "Best AI visibility tools" Ground truth entity set: Semrush, OtterlyAI, Rankshift, Promptwatch, Peec AI, Profound, Goodie AI, AthenaHQ, Scrunch AI, ChatGPT, Gemini, Perplexity, Claude, Microsoft Copilot, Google AI Overviews. This vertical was carried from WP001-004 giving the richest hallucination check baseline - every real tool in this space is known.

All entities generated by each model were checked against the ground truth lists and, where uncertain, verified independently.

3.2
Synonym and Subtopic Quality

Synonym and subtopic quality was evaluated on two criteria: specificity (are these specific to the query or generic to any topic?) and distinctiveness (are they meaningfully different from each other and from the core topic?).

Quality comparison across five dimensions for all three models.
Figure 4. Normalised quality scores (0-100) across five dimensions. Entity accuracy penalised for hallucinations (Gemini -20% for 3 hallucinated entities in V1). Subtopic specificity reflects whether subtopics are query-specific vs generic. Related concept depth reflects whether concepts would genuinely help downstream coverage analysis. Query universe size scores Gemini higher despite hallucinations - it generated more total items.

Notable finding on subtopics: Gemini produced the most strategically framed subtopics of the three models in V2 - "Full-Service vs. Niche Marketing Agencies," "Top-Rated Agencies by B2B vs. B2C Verticals," "Enterprise vs. SMB Digital Agencies" - which are more useful for content gap analysis than Claude's functional categories (SEO services, paid media, social media). This is an interesting tension: Gemini hallucinated entities but generated the best subtopics. The module needs to handle this asymmetry.

SECTION 4
Key Findings
F1
All three models produced valid topic universes
Despite the absence of page content as an anchor, all three frontier models generated coherent, well-structured topic universes across both verticals. Format compliance was perfect across all six models. The generative task is well within frontier model capabilities.
F2
Gemini hallucinated 3 entities in V1 - 20% rate
BrightEdge Generative Parser, Moz AI Analytics, and Preora do not exist as named products. This is Gemini's most serious failure across the five-paper series - in WP002-004 its errors were quantitative (inflation); here they are factual (fabrication). A hallucinated entity in the topic universe creates false gaps in every downstream analysis.
F3
Claude produced the cleanest entity list
Zero hallucinations across both verticals. All 15 V1 entities are real and verifiable. This is consistent with Claude's conservative, calibrated approach observed in WP001-004. Claude's instruction compliance ("do not invent entity names") was the strongest of the three models.
F4
ChatGPT covered the most ground truth entities
ChatGPT generated 11 of 15 ground truth entities for V1 - the highest coverage - and included AthenaHQ which Claude missed. Its V2 entity list covered both legacy holding companies (WPP, Dentsu, Publicis) and independent agencies (WebFX, KlientBoost, Ignite Visibility, Tinuiti) more comprehensively than Claude.
F5
Gemini's subtopic framing is the most strategically useful - asymmetry with entity quality
In V2, Gemini generated subtopics like "Full-Service vs. Niche Marketing Agencies," "Top-Rated Agencies by B2B vs. B2C Verticals," and "Enterprise vs. SMB Digital Agencies." Claude generated functional categories like "SEO and organic search services," "Paid media and PPC management." Gemini's subtopics are more useful for content gap analysis - they reflect the actual decisions a buyer makes, not just the service categories. This asymmetry (best subtopics, worst entity accuracy) means the module cannot use any single model for all six layers. The architecture should default to Claude for entities and could optionally use Gemini's subtopic framing as an enhancement layer.
F6
Two real entities missed by all three models - Rankshift and Promptwatch
Neither Rankshift nor Promptwatch appeared in any model's V1 entity list, despite both being real, active AI visibility platforms documented extensively in WP001-003. This is an expected limitation - models generate from training data, which has a knowledge cutoff, and newer entrants in niche markets may not be represented. This validates the need for the post-processing entity enrichment step: after model generation, the module should cross-reference the universe against a curated domain entity registry (maintained and updated by the user) to catch omissions that models cannot know about.
Series finding across WP001-005

WP005 confirms and extends the series-level pattern. Claude Sonnet 4.6 is production-ready across all five modules. ChatGPT GPT-5.5 is production-ready across all five. Gemini 3.5 Flash has a task-specific failure pattern in every paper: topic under-generation (WP002), aggressive boundary classification (WP003), over-estimated confidence (WP004), entity hallucination (WP005). WP005 reveals the most serious Gemini failure to date - fabricated entity names - which is qualitatively worse than the quantitative inflation observed in earlier papers. The AI Spider content intelligence suite recommends Claude as the default for all five modules, with the entity verification step as mandatory insurance regardless of which model is used.

SECTION 5
Implications for AI Spider
  • 01
    Mandatory entity verification step after generation
    Finding F2 establishes that even frontier models hallucinate entity names when generating without page content. The module will include a post-generation entity verification step: each named entity is checked against a domain registry and optionally web-verified before being added to the topic universe. Unverified entities are flagged as "unconfirmed" and excluded from downstream entity gap analyses until confirmed.
  • 02
    User-editable entity registry for domain-specific enrichment
    Finding F6 establishes that models miss real entities outside their training data. The module will maintain a user-editable entity registry per domain, allowing users to add known entities (like Rankshift or Promptwatch for AI visibility) that models consistently miss. These user-added entities are merged with the model-generated universe before downstream analyses run.
  • 03
    Layer-level model selection for asymmetric quality
    Finding F5 establishes that Gemini produces superior subtopics but inferior entities. The module architecture will allow layer-level model selection: Claude for entities (lowest hallucination risk), Gemini's subtopic framing available as an optional "strategic enhancement" that users can toggle on. This avoids forcing an all-or-nothing model choice when different models excel at different layers.
  • 04
    Query universe stored and reused across all modules
    The generated universe is stored in AI Spider's database and reused as the reference set for all subsequent CCI, Coverage Score, Retrieval Drift, and Coverage vs Confidence analyses for that query. This ensures consistency - the same entity list, subtopic set, and synonym set anchors every analysis. Running Query Expansion once per query rather than embedding it inside each module's prompt also reduces token cost across the platform.
  • 05
    Pre-analysis capability before any URLs are crawled
    Because Query Expansion requires no page content, it can run the moment a user enters a query - before they have selected any target or competitor URLs. This enables a new workflow: users see the full topic universe, verify it, and use it to inform which competitor pages to include in subsequent analyses. RankScan also uses the alternative queries layer to expand monitoring scope beyond the primary query automatically.

Next Steps
  • 6.1Module build - AI Spider Query Expansion tab: Runs on prompt input before any URL analysis. Generates six-layer topic universe. Includes entity verification step and user-editable registry. Stores universe in database for reuse. Claude Sonnet 4.6 as default entity generator; Gemini subtopic framing available as optional enhancement.
  • 6.2Domain entity registry: Build and maintain a curated entity registry for the AI/GEO tools vertical as the first domain. Cross-reference model-generated entities against the registry on every Query Expansion run. Publish the registry as an open reference for AI Spider users.
  • 6.3Cross-module universe propagation: Implement the shared universe store across all five content intelligence tabs. When a user runs Coverage Score or CCI after Query Expansion, the stored universe is automatically used as the expected topic and entity set - no re-generation needed, no inconsistency possible.
  • 6.4RankScan integration via alternative queries: Pass the alternative queries layer from Query Expansion to RankScan automatically. This expands brand monitoring scope beyond the primary query to all intent variations without requiring manual setup from the user.
  • 6.5Longitudinal study - WP006: Following full deployment of all five AI Spider content intelligence modules, measure AI citation rate changes via RankScan across 90 days for sites that implement module-informed content updates vs a control group. This is the evidence-based capstone of the series - does the full methodology produce measurable AI retrievability improvement?
